# 0.11.0 — 2026-10-16

## Added

- **`nws_get_alert`** ([#55](https://github.com/cyanheads/nws-weather-mcp-server/issues/55)) — one alert message by `alert_id`, including messages an update or cancellation has superseded. Takes an `id` or `references[].identifier` from `nws_search_alerts`, returns the same alert fields, and fails as `alert_not_found` for a malformed, unknown, or aged-out (~7 days) ID.
- **`nws_get_office_discussion` `sections` input** ([#50](https://github.com/cyanheads/nws-weather-mcp-server/issues/50)) — returns the header plus selected AFD sections by name, or ZFP/HWO/SPS zone segments by zone code. An unmatched name fails as `unknown_section` and lists the available ones.
- **`limit` accepts up to 10000** ([#53](https://github.com/cyanheads/nws-weather-mcp-server/issues/53)) on `nws_find_stations`, `nws_search_alerts`, and `nws_get_observation_history`. A limit past the page cap is served at the cap, with `requestedLimit` and `effectiveLimit` in the enrichment.
- **JSON Schema `pattern`s on ten string inputs** ([#54](https://github.com/cyanheads/nws-weather-mcp-server/issues/54)) — `alert_id`, `zone_id`, `office`, `station_id` (on both observation tools), `area`, `point`, `zone`, and `start`/`end`. Validation outcomes are unchanged.

## Changed

- **`nws_get_office_discussion` `productText` is absent on products over 24,000 bytes** ([#50](https://github.com/cyanheads/nws-weather-mcp-server/issues/50)) — most ZFPs now return `outline` (section names or zone segments with sizes) in its place. Re-call with `sections` to read the parts needed.
- **`no_products` wording is per product type** ([#59](https://github.com/cyanheads/nws-weather-mcp-server/issues/59)) — HWO and SPS keep the episodic message; an empty AFD or ZFP names the location-code mismatch, with Anchorage (`AER`, `ALU`) and San Juan (`PR`) ZFP codes.
- **`nws_get_forecast` hourly period `name`** ([#52](https://github.com/cyanheads/nws-weather-mcp-server/issues/52)) is the weekday and start time in the location zone (`Fri 6:00 AM`), and dewpoint °C is no longer rounded.
- **`marine_forecast_unsupported` on `nws_get_zone_forecast`** ([#57](https://github.com/cyanheads/nws-weather-mcp-server/issues/57)) — raised for coastal marine zones without a text forecast as well as offshore ones; coastal zones that serve one still return it.
- **Docker deps stage prunes musl-only packages** via `scripts/prune-musl-packages.ts`; `server.json` packages use `runtimeHint` `npx`, and the HTTP package sets `MCP_TRANSPORT_TYPE`.
- Scripts, config, and `framework-skills/` synced from mcp-ts-core 0.13.15; `getServerConfig()` runs in `setup()`.

## Fixed

- **`nws_get_observation_history` truncation** ([#51](https://github.com/cyanheads/nws-weather-mcp-server/issues/51)) — `truncated`, `cap`, and `nextCursor` appear only when an observation past the page exists; a window holding exactly `limit` observations no longer reports truncation.
- **`nws_get_observation_history` fractional seconds** — `start` and `end` with more than six fractional digits fail as `invalid_time_window` before any request.
- **`nws_search_alerts` `references` order** ([#56](https://github.com/cyanheads/nws-weather-mcp-server/issues/56)) — sorted newest first by parsed `sent` instant.
- **`nws_search_alerts` out-of-coverage `point`** ([#58](https://github.com/cyanheads/nws-weather-mcp-server/issues/58)) — fails as `invalid_point` with a recovery hint instead of a bare upstream 400.
