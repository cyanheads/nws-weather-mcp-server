# 0.9.5 — 2026-09-24

## Changed

- **Server `instructions`, README, and `docs/design.md` state that point and zone forecasts are land-only** — marine areas get alerts, plus stations and observations near the coast.
- **`CLAUDE.md`/`AGENTS.md` declare the release mode `gated`** — each release PR takes a separate `release-pr-review` pass before `release-and-publish`.

## Fixed

- **`marine_forecast_unsupported` (NotFound) on `nws_get_forecast` and `nws_get_zone_forecast`** ([#38](https://github.com/cyanheads/nws-weather-mcp-server/issues/38)) — raised for a gridpoint or zone 404 typed `MarineForecastNotSupported`, and for an offshore `/points` answer with no grid, which now fails after one request instead of as ServiceUnavailable.
- **`nws_find_stations` and `nws_get_observations` at an offshore point beyond the grid** ([#38](https://github.com/cyanheads/nws-weather-mcp-server/issues/38)) — an empty station list and `no_stations_nearby` respectively; `nws_get_forecast`'s `out_of_scope` recovery and the `nws_find_stations` zero-station notice no longer present marine areas as valid input.
- **`zone_forecast_unavailable` (NotFound) on `nws_get_zone_forecast`** ([#40](https://github.com/cyanheads/nws-weather-mcp-server/issues/40)) — a 404 typed `NotFound` or a 500 that outlives the retries is settled by one no-retry probe of `/zones/forecast/{id}`: a zone record means no text product, with recovery pointing to `nws_get_forecast`. `zone_not_found` now means a missing zone only.
- **`zone_id`, `station_id`, and `office` must be alphanumeric** ([#41](https://github.com/cyanheads/nws-weather-mcp-server/issues/41)) — anything else fails as the tool's not-found reason with no upstream request; URLs for valid IDs are unchanged.
- README VS Code install badge percent-encodes the `/` in the package name (`%2F`).
