# 0.10.0 — 2026-09-30

## Added

- **`nws_get_alert_counts`** ([#25](https://github.com/cyanheads/nws-weather-mcp-server/issues/25)) — national active-alert counts from `/alerts/active/count`: `totalAlerts`, `landAlerts`, `marineAlerts`, and sparse `areas` and `regions` maps. Takes no input; counts cover every message status, so `totalAlerts` can exceed a national `nws_search_alerts` `totalCount`.
- **`nws_get_observation_history`** ([#26](https://github.com/cyanheads/nws-weather-mcp-server/issues/26)) — one station's observations, newest first, back through the ~7 days NWS keeps, windowed by `start` (inclusive), `end` (exclusive), and `limit` (1-100, default 24). Pages upstream: `nextCursor` appears only on a full page, and `shown` is reported without a `totalCount`.

## Changed

- **Blank optional inputs are unset** ([#46](https://github.com/cyanheads/nws-weather-mcp-server/issues/46)) — a blank string, an empty array, an `event` array of blank terms, and a blank `region_type`, `status`, or `product_type` are treated as omitted. The `blank_location_filter`, `empty_filter_array`, and `blank_station_id` reasons are removed; advertised input schemas are unchanged.
- **Every declared `errors[]` reason sets `severity`** ([#43](https://github.com/cyanheads/nws-weather-mcp-server/issues/43)) — `notice`, or `warning` for `zone_forecast_unavailable`, so those `Error in tool:<name>` records leave the `error` log stream. Baseline faults still log at `error`; error envelopes are unchanged.
- **`zone_forecast_unavailable` carries a point inside the zone** ([#42](https://github.com/cyanheads/nws-weather-mcp-server/issues/42)) — `data.latitude`/`data.longitude`, derived from the zone record's geometry with no extra request, named in the message and in a recovery hint for `nws_get_forecast`. Omitted when the record has no usable geometry.
- **Dockerfile installs production dependencies in a `$BUILDPLATFORM` stage** — cross-installed with `--os`/`--cpu`, OpenTelemetry peers via `scripts/install-otel.ts`, so a multi-arch build no longer runs Bun under QEMU. The image no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- Scripts, config, and `framework-skills/` synced from mcp-ts-core 0.13.10: `lint-packaging` checks the `!dist/*.mcpb` files entry, `manifest.json` version parity, and the Dockerfile build platform; `lint-mcp` fails on a definition that does not import; `release-github --check` validates the tag annotation; `package.json` `files` excludes `dist/*.mcpb`.

## Fixed

- **`no_forecast_grid` (NotFound) on `nws_get_forecast`** ([#47](https://github.com/cyanheads/nws-weather-mcp-server/issues/47)) — a land point NWS serves no forecast grid for (interior Northern Mariana Islands) names its forecast zone and routes to `nws_search_alerts`, instead of a ServiceUnavailable. `nws_find_stations` and `nws_get_observations` give the gridless-marine no-stations answers there.
- **An exhausted 500 on `/points` or a `point` alerts search** ([#45](https://github.com/cyanheads/nws-weather-mcp-server/issues/45)) — the ServiceUnavailable names the point, and a `data.recovery.hint` covers both readings: an open-ocean point NWS always fails, or a land outage worth retrying. Retries and `data` are unchanged.
- **`nws_get_observations` by coordinates** ([#48](https://github.com/cyanheads/nws-weather-mcp-server/issues/48)) — a 404 on the nearest station's latest observation is `no_observations`, not `station_not_found`, matching the `station_id` path.
