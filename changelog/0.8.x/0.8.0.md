# 0.8.0 — 2026-08-12

**Breaking:** `affectedZones` entries are now `{ code, type }` objects, not bare zone-code strings.

```diff
- affectedZones: ["WAZ558"]
+ affectedZones: [{ code: "WAZ558", type: "forecast" }]
```

Read `.code` where a plain string was read before. Only `type: "forecast"` entries resolve via `nws_get_zone_forecast` — `county` and `fire` zones have no text forecast product (#31).

## Added

- **`nws_search_alerts`** gains `region_type` (`Land`/`Marine`) and `region` (marine groups: `AL`, `AT`, `GL`, `GM`, `PA`, `PI`) filters, mutually exclusive with `area`/`point`/`zone` and each other (#32).
- **Alerts** carry the CAP message lifecycle — `sent`, `effective`, `status`, `messageType`, and `references` (prior superseded messages) — alongside the existing hazard timing (#33).

## Changed

- **`nws_get_zone_forecast`**'s description and `zone_not_found` recovery text now name forecast-typed `affectedZones` entries specifically, resolved from the tool's declared error contract rather than a second hardcoded copy (#31).

## Fixed

- **`nws_search_alerts`** no longer fails the entire response when NWS omits an alert's `description` (e.g. some Coastal Flood Advisories); the field is now nullable (#37).
