# 0.12.1 — 2026-11-11

## Added

- **`nws_search_alerts` window search** ([#81](https://github.com/cyanheads/nws-weather-mcp-server/issues/81)): `start` and `end` return the alert messages issued in that window within NWS's 7-day retention, updates and cancellations included, paged by a tool-side keyset `cursor` over `sent`. `event` terms resolve to the `/alerts/types` names they match in part, since `/alerts` matches exact names only. Adds a `window` output field and notices for retention (messages before the cutoff may be missing), empty windows, and walks that cannot page past a tie.
- **`message_type`** (`Alert`, `Update`, `Cancel`) on `nws_search_alerts`, for active and window searches.
- **`seaLevelPressurePa`** on `nws_get_observations` and `nws_get_observation_history` ([#80](https://github.com/cyanheads/nws-weather-mcp-server/issues/80)): null on 5-minute records, which carry no `SLP` remark.
- **Expiry notice** on `nws_get_office_discussion` when every UGC segment returned is past its expiry ([#79](https://github.com/cyanheads/nws-weather-mcp-server/issues/79)); on SPS it points to `nws_search_alerts`.

## Changed

- **An `/alerts/types` body without type names** fails as SerializationError on `nws_list_alert_types`, `nws://alert-types`, and a windowed `event` search, instead of reading as an empty list or as no type matching.
- **`barometricPressurePa`** is described as the altimeter setting; observations render separate Altimeter and Sea-Level Pressure lines, and history gets one column for each ([#80](https://github.com/cyanheads/nws-weather-mcp-server/issues/80)).
- **`marine_forecast_unsupported`** on `nws_get_forecast` points to `nws_get_zone_forecast` and names the zone families that carry a text forecast; the gridless message names an offshore zone, and `nws_get_zone_forecast`'s description and recovery name the same families ([#82](https://github.com/cyanheads/nws-weather-mcp-server/issues/82)).
- **Date-time inputs** on `nws_get_observation_history` and `nws_search_alerts` accept lowercase `t`/`z` and offsets without a colon, sent upstream in canonical form.
- **Invalid-cursor recovery hints** on `nws_find_stations`, `nws_get_forecast`, `nws_get_observation_history`, and `nws_search_alerts` are plain text, with the parameter names as code spans in `content[]`.
- **`no_products`** message for SPS and HWO says what is on file rather than implying none is active.
- **`limit`** no longer has a 10000 ceiling on `nws_find_stations`, `nws_get_observation_history`, and `nws_search_alerts`.
- **Server `instructions`** and the `nws-weather-guide` skill (1.1) cover recent alerts, past-warning questions, expired statements, the altimeter/sea-level split, and which marine zone families carry a text forecast.
- **Timestamps rendered with a numeric UTC offset**, where no named time zone resolves, share one module-scope date formatter instead of building one per call; output is unchanged.
- **Bun engines floor raised to `>=1.4.4`** (mcp-ts-core 0.13.22). Node stays at `>=24.0.0`.
- **Framework sync:** skills, scripts, `.env.example`, and the changelog template follow `@cyanheads/mcp-ts-core` 0.13.22.

## Fixed

- **`nws_get_zone_forecast` `updated`** is corrected when NWS reads a midnight-hour (`12xx AM`) ZFP header as noon, with a `notice` naming NWS's value; any other `updated` later than the response comes back as sent, with a `notice` that it cannot be trusted ([#78](https://github.com/cyanheads/nws-weather-mcp-server/issues/78)).
- **inHg values** always show two decimals (`29.90`, not `29.9`).
- **Network failure** that outlives the retries is ServiceUnavailable instead of InternalError.
