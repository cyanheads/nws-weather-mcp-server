# 0.9.4 — 2026-09-19

## Changed

- **Tool error `content[]` now closes with `(reason <reason>)`** (mcp-ts-core 0.13.5) — every `ctx.fail`-thrown error on the 7 `nws_*` tools carries `data.reason`, so the text gains that trailing term. No `retryable` term appears: no tool here declares `retryable` in its `errors[]` contract.
- **Every tool argument rejection carries `data.reason: "invalid_arguments"` and a synthesized `data.recovery.hint`** (mcp-ts-core 0.13.3) — an unknown key, wrong type, or missing required field now returns a specific "Provide …" or accepted-key hint instead of the bare Zod diagnostic.
- **An unknown client-added root key, or an undeclared key that case-folds to exactly one declared field (e.g. `max_results` → `maxResults`), is now silently accepted** (mcp-ts-core 0.13.4) — an ordered pre-validation step runs before a call reaches a tool's schema. `inputSchema` is unchanged; no tool here declares its own `inputAliases`.
- **`sessionMode: 'stateless'` is declared explicitly in `src/index.ts`** rather than left to the `auto` default, which resolved to stateful. None of the 7 tools use `ctx.requestInput`.
- Error-contract reasons the NWS service layer throws are marked `thrownBy: 'service'` so `error-contract-unthrown` (mcp-ts-core 0.13.6) stops flagging them as dead.
- `isRetryableNwsError` now composes the framework's `defaultIsTransient` instead of re-implementing its transient-code set.
- `lint:packaging` gains a README version-badge parity check (mcp-ts-core 0.13.2); `scripts/build.ts` and devcheck's worker-TypeScript step resolve tsconfigs in either the `config/` or root layout.

## Fixed

- `nws_find_stations` and `nws_search_alerts` correct their empty-result text, which pointed callers to the enrichment block "above" instead of "below".
- README `Bun` badge now reads `v1.4.0%2B`, matching the `package.json` engines floor and shields.io's percent-encoding.
