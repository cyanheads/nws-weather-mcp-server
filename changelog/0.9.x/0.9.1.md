# 0.9.1 — 2026-08-25

## Changed

- **`@cyanheads/mcp-ts-core` `^0.12.3`** adopts MCP SDK v2 ([cyanheads/mcp-ts-core#305](https://github.com/cyanheads/mcp-ts-core/issues/305)). Every HTTP endpoint now also serves protocol revision 2026-07-28 alongside the existing 2025 revisions — current clients keep working unchanged. Tool inputs are strict: an argument key no tool declares is rejected by name instead of silently dropped. Advertised `inputSchema`/`outputSchema` are JSON Schema 2020-12 (was draft-07), and `outputSchema` now declares the error envelope alongside the success fields, so a client that validates `structuredContent` without checking `isError` stops rejecting error results.
- **`ctx.log` reaches the client.** Every handler log line also emits `notifications/message`, gated by the client's `logging/setLevel`.
- **Discovery results carry cache hints on the 2026 revision** ([cyanheads/mcp-ts-core#359](https://github.com/cyanheads/mcp-ts-core/issues/359)) — `tools/list`, `resources/list`, `server/discover`, and the `nws://alert-types` resource are cacheable for one hour, shared-cacheable. Forecasts, alerts, and observations are never cached: `tools/call` is not a cacheable operation.
- **Session mode settles on `stateless`.** `.env.example` and the README now document and set `MCP_SESSION_MODE=stateless` explicitly, matching the Dockerfile's existing container default — a source or local run now resolves the same session mode as the shipped image.
- **Bun pins move to `1.4.0`** — both `Dockerfile` stages and `packageManager` in `package.json`.
- Framework skills (`skills/`) re-synced to the versions shipped with `mcp-ts-core` `0.12.3`.

## Fixed

- **A failure after the handler returns is recorded as a failed call, not a silent success** ([cyanheads/mcp-ts-core#346](https://github.com/cyanheads/mcp-ts-core/issues/346)) — output-schema validation, `format()`, and the enrichment merge now fall inside the measured region.
- **A stdio client hanging up runs the full shutdown path** ([cyanheads/mcp-ts-core#322](https://github.com/cyanheads/mcp-ts-core/issues/322)) instead of leaving the process resident.
